# Replay sharpening: evidence and scope

This packet records the prediction-level diagnostic used in the release page. It is a finite-budget measurement of a vanilla NanoGPT run, not a schematic and not a claim that every memory system behaves the same way.

## Coordinates

- input route with clean bigram and trigram tables, 128× table learning-rate scale;
- matched no-gram control, same backbone setting and data order;
- seed 42, fixed shard-1 replay, 20 passes (337 updates per pass, 6,740 updates);
- BF16 diagnostic forward, probe every 10 updates, with epoch-boundary rows retained;
- validation diagnostics use the fixed validation batches.

The aggregate packet contains one row per run, branch, epoch, corpus-frequency bucket, and seen/novel group. mean_entropy and mean_margin are distribution-shape metrics. mean_ptrue and the separate CE packet depend on the true next token and therefore measure correctness or damage. The plot keeps these axes separate.

## How to read the result

In the local-memory run, entropy decreases and the probability margin grows across replay. At the same time, validation CE for novel continuations rises. The no-gram control also sharpens with optimization, but its novel-continuation CE follows a different trajectory. Thus “sharpening” describes output concentration; it does not by itself mean the prediction is correct. The context-level panel is illustrative of selected endpoints and should not be read as a monotonic trajectory for every context.

The result supports a scoped statement: under this fixed replay protocol, local memory can concentrate probability on training-compatible continuations while held-out novel continuations receive increasing loss. It does not establish independent context subspaces, a universal law, or equivalence to learned sparse routing.
